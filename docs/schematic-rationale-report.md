# 회로도 작성 근거 리포트 (2026-11-05)

이 문서는 회로도 작성 과정의 선택을 리뷰할 수 있게 정리한 것입니다. 사용자 의견을 그대로 반영한 것, 바꾼 것, AI(설계 도우미, 이 세션의 Claude)가 정한 것을 나누어 근거와 함께 적었습니다.

예제 회로 하나하나의 부품·값 근거는 회로 데이터(IR)의 `decisions`에 기록했습니다. 거기서 만든 예제별 리포트를 함께 보세요.

| 예제 | 리포트 | 결정 기록 | 기술 검토 (자동 계산) |
|---|---|---|---|
| 24V → 5V 레귤레이터 (7805) | [`examples/lm7805-24v-to-5v/rationale.md`](../examples/lm7805-24v-to-5v/rationale.md) | 요구 반영 2, 요구 수정 1, AI 선정 8 | 주의 1(발열), 참고 2, 통과 10 |
| NE555 LED 점멸 보드 | [`examples/ne555-led-board/rationale.md`](../examples/ne555-led-board/rationale.md) | 요구 반영 2, AI 선정 7 | 참고 2, 통과 5 |
| ATmega328P 상태 LED 보드 | [`examples/atmega328p-led-board/rationale.md`](../examples/atmega328p-led-board/rationale.md) | 요구 반영 1, AI 선정 6, 템플릿 1 | 참고 3, 통과 5 |

용어:
- **요구 반영**: 사용자가 요청한 대로 함.
- **요구 수정**: 요청과 다르게 함. 무엇을 왜 바꿨는지 적음.
- **AI 선정**: 요청에 없는 부분을 AI가 정함.
- **템플릿**: 검토된 템플릿이 정함.

자동 검사와 기술 검토는 설계 검증이 아닙니다. 세 예제 모두 엔지니어 검토 기록이 없습니다.

## 2. AI가 정한 회로도 그리기 규칙과 근거

사용자가 직접 요청하지 않았지만, 위 의견을 구현하면서 AI가 정한 규칙입니다. 바꾸고 싶은 규칙이 있으면 알려 주세요.

| 규칙 | 근거 | 대안과 버린 이유 |
|---|---|---|
| 연결은 배치와 무관하게 IR이 정하고, 배선은 다른 Net에 닿지 않을 때만 그린다(아니면 라벨). 완성된 페이지를 독립적으로 다시 검사한다. | 그림이 연결을 바꾸면 안 됩니다. 배선이 실패해도 라벨로 연결은 유지됩니다. | 무조건 배선: 다른 Net을 지나갈 위험 |
| 전원·GND는 KiCad 전원 심볼로 그린다. 단, 레귤레이터 블록의 입출력 레일은 선으로 긋는다. | 전원 심볼은 KiCad의 표준 관례이고 선이 줄어듭니다. 레귤레이터는 입출력선을 그리는 것이 교과서 표기입니다. | 모든 레일을 선으로: 보드가 커지면 선이 엉킴 |
| 선으로 이은 신호 묶음마다 이름 라벨을 하나씩 둔다. | KiCad·PCB에서 Net 이름이 `Net-(…)`로 바뀌지 않게 하려는 것입니다. | 라벨 생략: 이름을 잃음 |
| 선으로 이은 레일 묶음에는 라벨이 아니라 전원 심볼을 하나 둔다. | 루트 시트의 로컬 라벨은 전원 심볼과 다른 Net(`/+5V`)이 되어 연결이 끊깁니다. | |
| 배선 최대 길이 35.56 mm(14칸). 처음에는 30.48 mm였다. | 크리스탈 블록이 IC에서 조금 떨어져 XTAL1 선이 33 mm가 되었습니다. 이보다 긴 선은 페이지를 가로질러 읽기 어렵습니다. | 제한 없음: 긴 선이 다른 블록을 지나감 |
| 선에 매다는 부품은 선 위에 둔다(배치 탐색에서 선 밖은 칸당 5배 비용). | 한 줄로 이어진 체인(J1 → D1 → C → U1 → C → J2)이 읽기 쉽습니다. | 비용 1:3: 직렬 부품이 선 밖으로 비켜남 |
| 왼쪽으로 뻗은 선에 걸친 R·C는 좌우 반전해 글자를 바깥쪽에 둔다. | 글자가 IC 쪽을 향하면 부품이 IC에서 더 멀어집니다. | |
| 영문 주석은 기울임 글씨로, 부품 위·아래·옆 순서로 빈 자리에 놓는다. | Net 라벨과 구분하고, 다른 요소와 겹치지 않게 하려는 것입니다. 너무 길면 페이지 위쪽으로 밀리므로 40자 안팎을 권합니다. | |
| 반전·회전 순서는 KiCad와 같게(회전 후 반전). | KiCad 10.0.8로 90°·270° 회전과 반전을 함께 건 부품을 확인하다 버그를 찾아 고쳤습니다. 이전 자동 배치에는 그런 부품이 없어 결과가 같았습니다. | |
| PWR_FLAG는 생성기가 자동으로 넣는다. | 커넥터나 직렬 부품으로 들어오는 전원에 ERC "구동원 없음" 오류가 나지 않게 하려는 것입니다. | 사용자가 직접 넣기: 빠뜨리기 쉬움 |

## 3. 기록하는 근거와 리뷰 방법

- **회로 데이터(IR) `decisions`:** 결정마다 주제, 선택, 누가 정했는지(요구 반영/요구 수정/AI 선정/템플릿/엔지니어), 근거, 사용자 원문, 계산식, 출처(데이터시트 절), 관련 부품을 남깁니다.
  - AI 설계는 부품마다 이 항목을 채우도록 요청받고, 근거를 남기지 않으면 "AI가 이유를 남기지 않았습니다"로 기록됩니다.
  - 템플릿은 데이터시트 근거를 남깁니다.
  - 직접 제안에는 "이유" 칸이 있습니다.
- **근거 리포트:** 앱 「문서 · BOM → 근거 리포트」, 생성 결과물 `outputs/rationale.md`, 명령 `aics report`로 볼 수 있습니다. 내용은 다음과 같습니다.
  - 요구사항 원문
  - 결정과 근거(누가 정했는지별)
  - 부품별 근거(근거가 없는 부품 표시)
  - 기술 검토 결과
  - 변경 이력(제안 근거, AI 가정·질문·데이터시트 인용, 승인·거부)
  - 리뷰 체크리스트
- **기술 검토(자동 계산):** 「검토」 탭 위쪽에 있습니다. 항목은 콘덴서 정격 전압·극성, LED 방향·직렬 저항·전류, 저항 소비 전력, 레귤레이터 드롭아웃·발열, IC 디커플링입니다.
  - 계산식과 가정을 함께 보여 줍니다.
  - 전압은 Net 이름에서 읽습니다. 전압을 알 수 없는 Net은 "계산에서 뺐다"고 알립니다.

## 4. 한계와 확인할 것

- 이 세션에는 AI 키가 없어 실제 Gemini/Claude 설계를 돌리지 않았습니다. 예제의 결정 기록은 이 세션의 AI(Claude)가 직접 내린 결정을 사람이 읽을 수 있게 옮긴 것입니다.
- 데이터시트 사이트가 이 환경에서 막혀 있어 원문 쪽 번호는 적지 않았습니다. 출처에는 문서와 절만 적고, 필요한 곳에는 "쪽 번호는 원문 확인 필요"라고 남겼습니다. 값(드롭아웃 약 2 V, TO-220 열저항 약 50 °C/W 등)은 일반적인 데이터시트 값이므로, 쓰는 제조사 데이터시트로 확인해야 합니다.
- 7805 예제의 출력 전류(100 mA)는 가정입니다. 실제 부하 전류로 발열을 다시 계산해야 합니다.
- 세 예제 모두 엔지니어 검토 기록이 없습니다. 「검토」 탭에서 기록해야 `verified`가 됩니다.
