# ADR-007: 회로 템플릿의 출처·책임과 엔지니어 검토 기록

- 상태: **채택(Accepted)** — Phase 3 구현과 함께
- 날짜: 2026-11-05
- 관련: 기획서 v1.7 10.1절(상태 3축), 12장 Phase 3, 18장("템플릿의 검증/승인 책임과 출처 관리 정책 — Phase 3 시작 전 결정 필요")

## 배경

Phase 3는 "검토된 템플릿"(전원부, MCU 최소 회로, CAN 회로)과 "엔지니어 검토 기록"을 요구한다. 기획서 18장은 템플릿을 누가 검증하고 출처를 어떻게 관리할지를 미정으로 남겼다. 또 10.1절은 `verified`를 사람만 설정할 수 있다고 정했지만, 지금까지 이 축은 IR의 `validation.status` 값을 그대로 보여 줬을 뿐 근거 기록이 없었다.

## 결정

### 템플릿

1. **템플릿은 코드다.** `circuit_core/templates.py`에 있고, 바꾸려면 저장소 코드 검토를 거친다. 템플릿마다 `id@version`이 있고, 보드에 놓인 부품은 `origin = "template:<id>@<version>"`을 갖는다(IR 0.4.0). AI가 만든 템플릿이나 사용자가 앱에서 만든 템플릿은 이 단계에서 지원하지 않는다.
2. **근거는 제조사 데이터시트의 응용 회로다.** 템플릿마다 데이터시트(문서 이름, KiCad 심볼의 링크)와 각 선택의 근거가 되는 **절 이름**을 적는다.
   - **쪽 번호는 적지 않는다.** 이 개발 환경에서는 데이터시트 사이트가 네트워크 정책으로 막혀 원문을 열 수 없었다. 쪽 번호는 지어내지 않고, 데이터시트를 직접 확인한 엔지니어가 검토 기록에 남긴다.
   - 설계자가 정해야 하는 값(인덕터, 크리스탈 부하 커패시터, 종단 저항 여부)은 체크리스트에 "확인할 결정"으로 적는다.
3. **템플릿은 검토의 시작점이다.** 템플릿을 놓아도 아무것도 `verified`가 되지 않는다. 템플릿 부품은 처음에 `needs_review`다.
4. **템플릿도 보드에 들어가는 길은 하나다.** 「템플릿」 탭에서 넣으면 제안(source `template`)이 만들어지고, 승인해야 revision이 된다. 단자 Net은 이름으로 보드의 Net에 이어진다. 기호·id는 겹치지 않게 정해지고, 내부 Net 이름이 이미 쓰이고 있으면 바꾼다.
5. **검증 기준:** 템플릿마다 시험 회로(템플릿 + 단자 커넥터)를 만들어 IR 규칙, 생성, KiCad 10.0.8 ERC 0건, Netlist = IR을 확인한다(`tests/test_templates.py`). 풋프린트 이름은 KiCad 10.0.8 라이브러리에 실제로 있는지 확인했다.
6. **AI 설계는 템플릿을 우선 쓴다.** 계획 단계에서 템플릿 목록을 받고, 고른 템플릿은 코드가 펼쳐 고정한다. AI는 자기 부품만 템플릿의 단자 Net 이름으로 잇는다. 템플릿 핀을 직접 연결하거나 내부 Net 이름을 쓰면 수정 요청으로 돌려보낸다.

### 엔지니어 검토 기록

7. **검토 기록만 엔지니어링 검토 축을 바꾼다.** 기록은 `boards/<b>/reviews/<id>.json`에 저장하고 고치지 않는다. 내용은 검토자, 검토한 revision, 범위(보드 전체 또는 부품), 확인한 데이터시트(개정, 쪽), 체크 항목별 결과(확인/문제/해당 없음과 메모), 결과(`verified` 또는 `needs_changes`)다.
8. **상태 계산 (현재 revision 기준):**
   - `verified`: 이 revision의 `verified` 검토가 덮는 부품.
   - `needs_review`: 템플릿·AI 출신 부품, 이전 revision에서만 검토된 부품, 또는 마지막 검토가 수정 필요인 부품.
   - `unverified`: 그 밖(직접 넣고 검토하지 않은 부품). 보드 상태는 부품 상태를 합친다.
9. **`verified`로 저장하려면 조건이 있다.** 문제 항목이 없어야 하고, 범위 안 템플릿의 체크리스트를 모두 기록해야 한다(확인 또는 해당 없음). 오래된 revision은 기록할 수 없다.
10. AI·자동 검사·Agent에는 검토 기록을 쓰는 경로가 없다. 헤더의 「엔지니어링 검토」 칩은 IR의 `validation.status`가 아니라 검토 기록에서 계산한다.

## 검토한 다른 안

| 안 | 판단 |
|---|---|
| 템플릿에 쪽 번호를 미리 적기 | 원문을 확인하지 못했으므로 쓰지 않는다. 틀린 쪽 번호는 근거가 없는 것보다 나쁘다. |
| 템플릿을 사용자가 앱에서 만들고 공유 | 검토·버전 관리 체계가 먼저 필요하다. 나중 단계 후보. |
| 템플릿 부품을 `verified`로 시작 | 데이터시트 응용 회로도 사용 조건(전압, 전류, 레이아웃)에 따라 달라진다. 보드마다 사람이 확인해야 한다. |
| IR `validation.status`를 검토 결과로 덮어쓰기 | 검토만으로 새 revision이 생겨 이력이 어지러워진다. 상태는 기록에서 계산한다. |

## 남은 위험

- 템플릿 값(예: AMS1117 출력 탄탈 22µF, LM2596 33µH)은 데이터시트 원문 대조 전이다. 체크리스트와 `needs_review`로 드러나게 했지만, 원문 확인은 사용자 몫이다.
- 검토자 이름은 본인 확인이 없는 자유 입력이다(로컬 단일 사용자 앱 전제).
