# ADR-015: 연구노트 — 회로 검토에서 배운 것을 동료가 쓸 수 있게 남기기

- 상태: **채택(Accepted)**
- 날짜: 2026-11-06
- 관련: ADR-004(AI 공급자), ADR-011(설계 결정과 기술 검토), ADR-013(설계 가이드)

## 배경

사용자 요청: "회로 개발 엔지니어가 회로 검토하면서 학습하거나 깨달은 것, 나중에는 적용할 것 등을 기록하는 연구노트를 작성하는 것처럼 AI가 회로 검토 시 노트를 작성해주면 좋겠어. 다른 사람이 봐도 이해할 수 있고 써먹을 수 있도록."

이미 있는 것과 다른 점:
- **AI 검토 의견**은 "이 회로의 무엇이 문제인가"(지적 목록)이고, 보드의 최신 결과만 남는다.
- **설계 가이드**(ADR-013)는 다음 설계에 지킬 규칙(명령문)이다. 왜 그런 규칙이 생겼는지, 어떤 회로에서 무엇을 보고 알게 됐는지는 짧은 출처 한 줄뿐이다.
- **근거 리포트**(ADR-011)는 한 보드의 결정과 이력이다.

연구노트는 그 사이를 채운다. 무엇을 어떻게 확인했고, 그래서 무엇을 배웠고, 다음에 무엇을 할지를 사람이 읽는 글로 남긴다.

## 결정

1. **노트 형식은 고정된 절로 한다.** 누가 읽어도 같은 자리에서 같은 내용을 찾게 하기 위해서다.
   - 머리: 번호(N-0001), 제목, 대상(프로젝트·보드·revision·제안), 작성자(AI 모델 또는 사람), 상태(초안·검토함), 부품, 분야(설계 가이드와 같은 분야 목록).
   - **요약**, **배경**(목적·주요 부품·조건), **확인한 것**(항목 | 어떻게 확인했나 | 결과 | 판단 | 근거), **배운 점·깨달은 점**, **다음 설계에 적용할 것**(할 일 — 이유), **열린 질문**(측정·원문 확인처럼 아직 답이 없는 것), **근거**(인용한 항목 전문).
   - Markdown으로 보여 주고 내려받는다(노트 하나 또는 노트 전체).
2. **AI는 앱이 준 근거만 인용한다.** 노트를 쓰기 전에 앱이 그 회로에 대해 아는 것을 번호 붙인 목록(E1, E2 …)으로 만든다.
   - 내용: 기술 검토 계산(규칙·계산식), 데이터시트 대조 결과와 요약의 정격·외부 부품·메모(쪽 번호 포함, 원문 확인 여부), 설계 지침 체크리스트에서 위반·확인 필요·예외인 것, 설계 결정, KiCad·IR 검사, 제안의 검사 결과, AI 검토 의견, 요구사항. 최대 80개.
   - AI는 문장마다 근거 번호를 적는다. 앱은 목록에 있는 번호만 남기고(없는 번호는 버림), 근거 목록을 노트와 함께 저장해 회로가 바뀐 뒤에도 무엇을 보고 쓴 글인지 읽을 수 있다.
   - 근거 없이 쓴 배운 점은 「근거 없음: AI의 일반 지식, 확인 필요」로 표시한다.
   - 쪽 번호는 데이터시트 요약에서만 온다. 글에 쪽 번호가 있는데 인용한 근거에 그 쪽이 없으면 「쪽 번호 근거 없음: 원문 확인 필요」를 붙인다.
3. **AI가 쓴 노트는 초안이다.** 사람이 읽고 「검토함으로 표시」해야 확인된 노트가 된다(이름과 시각이 남음). AI 결과를 사람이 확인하기 전에는 확정하지 않는다는 원칙(ADR-004)과 같다. 사람이 직접 쓴 노트는 쓴 사람이 확인한 것으로 본다.
4. **고치면 새 버전이고, 바꾼 줄은 바꾼 사람의 것이다.** 그대로 둔 줄은 원래 작성자(AI)와 근거를 유지하고, 바뀌거나 새로 쓴 줄은 「사람이 고침」으로 표시한다. 고친 전·후는 `history.jsonl`에 남는다. 초안만 지울 수 있고, 검토함인 노트는 지우지 않는다(연구노트는 나중에 고쳐 쓰지 않고 버전으로 남긴다).
5. **다음에 적용할 것은 설계 지침 후보로 넘긴다.** 「지침 후보로」를 누르면 그 항목이 설계 가이드의 **후보**가 되고(출처: 연구노트 번호·제목·보드), 노트에 지침 번호가 붙는다. 채택은 설계 가이드에서 사람이 한다(ADR-013).
6. **언제 쓰나.**
   - 「검토」 탭의 연구노트 카드: **AI로 연구노트 쓰기**(특히 다룰 것을 적을 수 있음).
   - 「제안」 탭의 AI 검토(현재 회로·제안): **AI 검토 때 연구노트도 쓰기**를 켜 두면 검토 결과까지 근거에 넣어 노트를 함께 쓴다(AI 호출 1회 추가, 기본 켜짐, 브라우저에 기억). 노트가 실패해도 검토 결과는 남는다.
   - 보내기 전에 받는 곳·모델·보낼 내용(회로 글자 수, 근거 개수와 종류, 다룰 것)을 보여 주고 확인을 받는다.
7. **노트는 워크스페이스 공통이다**(`<workspace>/notes/`: `notes.json`, `history.jsonl`, `ai_runs/`). 설계 가이드·데이터시트처럼, 한 보드에서 배운 것을 다음 프로젝트에서 찾게 한다. 사이드바 **연구노트**에서 검색(부품·단어)·상태로 거르고, 모두 Markdown으로 내려받는다. 보드의 「검토」 탭에는 그 보드의 노트만 보인다.

## 검토한 다른 안

| 안 | 판단 |
|---|---|
| AI 검토 의견에 "배운 점" 칸만 추가 | 검토 의견은 보드의 최신 결과만 남고, 사람이 고치거나 확인한 기록이 없다. 따로 쌓이는 노트로 했다. |
| 설계 가이드에 바로 넣기 | 가이드는 규칙이라 짧아야 한다. 배경과 이유는 노트에 두고, 규칙이 될 것만 후보로 넘긴다. |
| AI가 자유롭게 쓰게 두기 | 동료가 그대로 믿고 쓰면 틀린 숫자·쪽 번호가 퍼진다. 근거 번호를 강제하고, 근거 없는 문장을 표시한다. |
| 노트를 보드 폴더에 저장 | 다른 프로젝트에서 찾기 어렵다. 워크스페이스 공통으로 하고 보드 정보를 노트에 둔다. |

## 검증

- `tests/test_research_notes.py`(가짜 AI): 근거 목록(계산·설계 결정·요구사항이 들어감), 없는 근거 번호 버림·소문자 번호 읽기, 모르는 분야 버림, 근거에 없는 쪽 번호 표시, Markdown 절, AI 실행 기록에 키 없음, 고친 줄만 사람 표시·근거 유지·전후 이력, 이름 없는 검토 거부, 검토한 노트 지우기 거부, 지침 후보 만들기·중복 거부, 사람이 쓴 노트, 검색·상태·보드 필터, 내보내기, AI 검토와 함께 쓰기(검토 결과가 근거에 들어감, 끄면 안 씀).
- `desktop/src/notes.test.ts`: 편집기의 한 줄 형식 왕복, 상태·대상 표시.
- `desktop/e2e/notes.spec.ts`(가짜 AI): I2C 예제에서 「AI로 연구노트 쓰기」 → 확인 창의 보낼 내용 → 초안·근거 표시 → 검토함 → 지침 후보 → 사이드바 연구노트 → 직접 쓴 노트 → 검색.

## 남은 위험

- **실제 모델로는 아직 써 보지 않았다.** 가짜 AI로 형식과 근거 처리만 확인했다. 실제 모델이 근거 번호를 잘 다는지, 교훈을 일반화해서 쓰는지는 사용자 시험이 필요하다.
- 근거 번호가 붙어 있어도 문장이 근거를 잘못 요약할 수 있다. 그래서 인용한 근거 전문을 노트 끝에 보여 주고, 사람이 「검토함」으로 확인하게 한다.
- 노트가 많아지면 찾기 어렵다. 지금은 단어 검색과 상태·보드 필터뿐이다. 분야·부품별 묶어 보기는 필요하면 더한다.
