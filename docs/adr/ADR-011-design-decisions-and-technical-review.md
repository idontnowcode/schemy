# ADR-011: 설계 결정 기록, 계산 기반 기술 검토, 근거 리포트

- 상태: **채택(Accepted)**
- 날짜: 2026-11-05
- 관련: 기획서 10장 L3 Engineering, 10.1절 상태 3축, ADR-006(AI 회로 설계), ADR-007(템플릿과 엔지니어 검토), IR 0.7.0·0.8.0

## 배경

사용자 요청: "사용자 의견에 대해 수용한 부분, 수정한 부분, AI가 선정한 부분 등 선택의 근거를 기록하면 내가 리뷰할 수 있게", "작성된 회로를 기술적으로 리뷰하는 기능".

그전까지 근거는 흩어져 있었다. 제안의 `rationale`(제안 한 건의 설명), AI 실행 기록의 가정·인용, 부품의 `origin`(템플릿/AI)은 있었지만, "이 부품을 왜 이 값으로 골랐는가"를 회로와 함께 남기는 곳이 없었다. 기술 검토는 데이터시트 대조(ADR-005)와 AI 검토(ADR-006)뿐이었다. 데이터시트 요약이 있어야 동작하고, AI 검토는 계산 근거를 보장하지 않는다.

## 결정

### 1. 설계 결정은 회로(IR)에 남긴다 (IR 0.7.0 `decisions`)

- 결정 하나 = 주제(`topic`), 선택(`choice`), 누가 정했는지(`by`), 이유(`reason`), 그리고 선택 사항으로 원래 요청(`request`), 계산(`calc`), 출처(`source`), 관련 부품(`components`).
- `by`는 다섯 가지다. 사용자가 리뷰할 때 가장 먼저 가르는 기준이기 때문이다.

| `by` | 뜻 | 규칙 |
|---|---|---|
| `requirement` | 사용자 요구를 그대로 반영 | |
| `changed` | 사용자 요구를 바꿈 | `request`(원래 요청)가 없으면 경고 `DECISION_REQUEST_MISSING` |
| `ai` | AI가 정함 (요구에 없던 것) | |
| `template` | 검토된 템플릿이 정함 | 템플릿을 넣을 때 자동 기록, 출처 = 템플릿의 데이터시트 절 |
| `engineer` | 엔지니어가 정함 | 「제안」 탭에서 직접 적음 |

- 회로 밖(별도 파일)이 아니라 IR에 둔 이유: revision과 함께 저장되고, 제안 비교 표에 바뀐 결정이 나오고, 회로를 다른 곳으로 옮겨도 근거가 따라간다.
- 바꾸는 길은 제안뿐이다. patch 연산 `set_decision`(바꿀 때는 `expect_choice`로 현재 선택을 밝힘), `remove_decision`.
- 부품을 지우면 결정은 남기고 그 부품만 뺀다. "왜 지웠는가"도 근거이기 때문이다(주석은 대상이 없으면 지운다).
- AI 회로 설계는 부품마다 `reason`, `basis`(requirement/changed/ai), `request`, `calc`를 내야 한다. 이유를 비우면 "AI가 이유를 남기지 않았습니다"로 기록해 빈칸이 보이게 한다.

### 2. 기술 검토는 코드가 계산한다 (`circuit_core/engineering.py`)

- AI가 아니라 규칙과 계산이다. 같은 회로면 같은 결과가 나오고, 결과마다 계산식을 보여 준다.
- 결과는 `fail`(실패) / `warn`(주의) / `info`(참고, 계산할 수 없음) / `ok`(통과).
- 규칙:

| 규칙 | 내용 |
|---|---|
| 콘덴서 정격 전압 | 값에 적힌 정격(`10uF/16V`)과 양단 전압. 정격 < 전압이면 실패, 1.5배 미만이면 주의, 정격이 없으면 참고 |
| 극성 콘덴서 | + 단자가 더 낮은 전압이면 실패 |
| LED | 방향(애노드가 더 낮으면 실패), 직렬 저항 없이 레일에 바로 걸리면 실패, 전류(색별 Vf 범위로 계산, 20 mA 초과면 주의). IC 핀으로 구동하면 전원 전압을 상한으로 계산 |
| 저항 소비 전력 | 크기별 일반 정격(0201~2512, 리드형 0.25 W)의 50% 초과면 주의, 100% 초과면 실패 |
| 리니어 레귤레이터 | 드롭아웃(78xx 약 2 V, 1117 약 1.1~1.3 V)보다 입출력 차가 작으면 실패. 발열 = 입출력 차 × 부하 전류, 1 W 이상이면 주의(TO-220은 방열판 없음 약 50 °C/W·주변 25 °C로 접합 온도도 계산). 부하 전류를 모르면 100 mA 기준. 시리즈 최대 출력 전류(78L 0.1 A, 78M 0.5 A, 78 1.5 A, AMS1117 1 A, LD1117·LM1117 0.8 A)를 넘으면 실패 |
| 다이오드 | 직렬 다이오드: 뒤쪽 Net 전류 ↔ 평균 순방향 전류 정격(70% 초과 주의), 손실 = Vf × I. 역방향으로 걸린 다이오드: 역전압 ↔ VRRM(80% 초과 주의). 정격은 품번(1N400x, 1N540x, 1N581x, 1N582x, SS1x, SS3x, 1N4148)의 일반값 |
| 디커플링 | IC 전원 핀의 Net에 GND로 가는 콘덴서가 없으면 주의 |
| I2C 풀업 | SDA·SCL Net에 전원으로 가는 저항이 없으면 주의(다른 보드에 있으면 무시) |
| 크리스탈 | 양 끝에 GND로 가는 부하 콘덴서가 없으면 주의. 있으면 CL ≈ C1·C2/(C1+C2) + 배선 3~5 pF 계산 |
| 전압을 모르는 전원 Net | 전압을 쓰는 계산에서 빠졌다고 알림. 커넥터 신호(TXD 등)는 전원으로 보지 않음 |

- 전압은 Net에 적은 값(`Net.voltage`, IR 0.8.0), 없으면 Net 이름(`+5V`, `+3V3`, `VCC_12V`)에서 읽는다. 데이터시트 대조(ADR-005)도 같은 값을 쓴다.
- 전류는 Net에 적은 부하 전류(`Net.load_current`, 암페어)를 쓴다. 비어 있으면 그 Net이 레귤레이터·직렬 다이오드로 넘겨 주는 뒤쪽 Net의 전류를 더한다(예: 7805 입력 Net의 전류 = 출력 Net의 부하 전류).
- **설계 검증이 아니다.** 결과는 「검토」 탭에서 엔지니어가 확인할 목록으로만 쓴다. 상태 3축의 어느 값도 바꾸지 않는다. `verified`는 여전히 엔지니어 검토 기록(ADR-007)만 정한다.

### 3. 근거 리포트는 위 둘과 제안 이력을 묶은 Markdown이다 (`circuit_core/rationale.py`)

- 차례: 요약 → 요구사항 원문 → 설계 결정(누가 정했는지별) → 부품별 근거(결정이 없는 부품은 **근거 기록 없음**) → 기술 검토 → 변경 이력(제안 근거, AI 가정·질문·데이터시트 인용, 승인·거부) → 회로도 주석 → 리뷰할 때 확인할 것(체크리스트).
- 볼 수 있는 곳: 앱 「문서 · BOM → 근거 리포트」(현재 시각, 대기 중 제안 포함), 생성 결과물 `outputs/rationale.md`(결정이 끝난 제안만, 시각 없음 — 같은 revision이면 같은 파일), 명령줄 `aics report circuit.json`(회로 파일만, 제안 이력 없음).
- API: `GET …/boards/{id}/documents/rationale`, `GET …/boards/{id}/technical-review`.

### 4. 전원 조건(Net 전압·부하 전류)은 계산 입력이다 (IR 0.8.0)

- 이름만으로는 정확하지 않은 경우가 많다. 입력 커넥터 Net은 이름에 전압이 없고(`PWR_IN`), 직렬 다이오드 뒤 Net은 이름보다 0.7~1 V 낮다. 부하 전류는 이름으로 알 수 없다.
- 그래서 Net에 `voltage`(V)와 `load_current`(A)를 둔다. 계산에만 쓰고 연결과 회로도 그리기에는 쓰지 않는다(전원 심볼 여부는 계속 이름으로 정한다).
- 바꾸는 길은 제안이다: patch 연산 `set_net_spec`(현재 값을 `expect_voltage`·`expect_load_current`로 밝힘). 「검토」 탭의 「전원 조건」 표에 적으면 제안이 만들어지고, 제안 비교 표에 「전원 조건」으로 나온다.
- 이름의 전압과 적은 전압이 10% 넘게 다르면 경고 `NET_VOLTAGE_MISMATCH`(다이오드 강하 정도는 허용).
- AI 회로 설계는 연결 단계에서 전원 Net마다 전압·부하 전류(가정 포함)를 `rails`로 낸다.
- 근거 리포트의 기술 검토 절에 「계산에 쓴 전원 조건」(적은 값인지, 이름에서 읽었는지, 뒤쪽 Net에서 계산했는지)을 함께 적는다.

## 버린 대안

- **근거를 제안(proposal)에만 둠:** 제안은 한 번의 변경 단위라, 여러 제안을 거친 부품의 근거를 모으려면 이력을 다 뒤져야 한다. 회로를 복원하거나 내보내면 근거가 끊긴다.
- **AI가 기술 검토:** 이미 「AI 검토」가 있다. 계산 근거가 보장되지 않고, 같은 회로에서 결과가 달라질 수 있다. 숫자로 확인할 수 있는 항목은 코드가 계산하고, AI 검토는 그 밖의 의견용으로 둔다.
- **SPICE 시뮬레이션:** 기획서상 L4(시뮬레이션·시험)는 MVP 밖이다. 부품 모델과 부하 조건이 없으면 숫자가 오히려 오해를 만든다.

## 한계

- 전압·부하 전류를 적지 않으면 Net 이름과 100 mA 기준으로 계산한다. 적은 값이 맞는지는 앱이 확인하지 않는다.
- 부하 전류는 Net 단위다. 부품마다의 소비 전류를 더해 주지는 않는다(적은 값이 그 Net의 전체 부하).
- 규칙이 수동 부품, LED, 리니어 레귤레이터, 다이오드, 디커플링, I2C 풀업, 크리스탈에 한정된다. 스위칭 레귤레이터·트랜지스터·MOSFET·OP앰프·로직 레벨은 보지 않는다.
- 정격 값(Vf, 드롭아웃, 열저항, 저항 크기별 정격)은 일반값이다. 실제 부품의 데이터시트로 확인해야 하고, 결과에도 그렇게 적는다.
- AI가 적은 이유와 출처를 앱이 확인하지는 않는다. 데이터시트 쪽 번호는 원문 확인 전이면 "원문 확인 필요"로 적는다.
