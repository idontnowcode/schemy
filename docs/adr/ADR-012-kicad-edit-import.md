# ADR-012: KiCad에서 고친 연결·값·부품 가져오기 (외부 수정 가져오기 2단계)

- 상태: **채택(Accepted)**
- 날짜: 2026-11-05
- 관련: 기획서 13장 "양방향 편집 데이터 충돌", ADR-010(1단계: 배치), ADR-002(KiCad 10.0.x)

## 배경

1단계(ADR-010)는 KiCad에서 옮긴 **배치**만 가져왔다. KiCad에서 선을 고치거나, 값을 바꾸거나, 부품을 넣고 지우면 앱은 "외부에서 수정됨"이라고만 알렸고, 다시 생성하면 그 수정이 사라졌다.

## 결정

1. **연결은 KiCad가 읽은 대로 가져온다.** 앱이 회로도 파일의 선·라벨·접점을 직접 해석하지 않는다. `kicad-cli sch export netlist`로 KiCad가 만든 Netlist를 받아 회로(IR)와 비교한다. 연결 해석의 기준이 KiCad 하나로 남고, 앱의 KiCad 검사(Netlist ↔ IR)와 같은 방식이다. 그래서 **kicad-cli가 필요하다.** 없으면 `KICAD_UNAVAILABLE`이고, 배치만 가져오는 1단계는 그대로 쓸 수 있다.
2. **부품은 `AICS_ID`로 짝짓는다.** 기호(R1)는 바뀔 수 있어서 기호로 짝짓지 않는다.
   - `AICS_ID`가 없는 심볼은 KiCad에서 추가한 부품이다. 라이브러리에서 심볼의 핀을 읽어 `add_component`로 넣는다(id `kicad-<기호>`, 위치는 자동 배치). 기호가 정해지지 않았거나(`U?`), 라이브러리에 없거나, 다른 부품과 기호가 겹치면 넣지 않고 알린다.
   - 회로에 있는데 KiCad에 없는 부품은 `remove_component`다.
   - 값·풋프린트가 다르면 `set_property`다(현재 값을 `expect`로 밝힌다).
   - 기호 변경과 심볼 교체는 가져오지 않고 알린다. 기호를 바꾸는 patch 연산이 없고, 심볼 교체는 핀이 달라져 연결 전체를 다시 봐야 하기 때문이다.
3. **연결은 핀마다 비교한다.** 각 핀의 Net이 회로와 다르면 이전 Net에서 `disconnect`, 새 Net에 `connect`한다.
   - Net 이름은 KiCad의 라벨·전원 심볼 이름을 쓴다. 생성기는 모든 Net에 이름을 붙이므로 고치지 않은 Net은 이름이 같다.
   - KiCad가 스스로 지은 이름(`Net-(R1-Pad2)`)은 핀이 가장 많이 겹치는 회로의 Net 이름을 이어받는다. 라벨을 지웠지만 선이 그대로라면 바뀐 것이 없다. 겹치는 Net이 없으면 KiCad 이름에서 새 이름을 만든다.
   - 핀이 그대로인데 라벨 글자만 바뀌었으면 `rename_net`이다.
4. **배치도 함께 가져온다.** 생성기가 이 revision에서 그린 위치와 다른 부품만 `move`한다. 1단계처럼 모든 부품을 고정하지 않는다.
5. **바꾸는 길은 제안 하나다.** 모든 변경은 patch 연산 목록으로 제안(출처 `kicad_edit`)에 들어간다. 비교 표, IR 규칙 검사, KiCad 검사를 거쳐 사람이 승인해야 회로에 들어간다. 승인하고 다시 생성하면 고친 파일을 덮어쓴다. 그 내용은 이미 회로에 들어왔기 때문이다. 가져오지 못한 것은 제안 설명과 화면에 적는다.
6. **조건:** 출력 회로도가 현재 revision에서 생성된 것이어야 한다(`OUTPUTS_STALE`). 바뀐 것이 없으면 `NO_KICAD_CHANGES`다.

## 버린 대안

- **회로도 파일(.kicad_sch)을 직접 해석:** 선이 핀 끝·선 중간에 닿는 규칙, 접점, 라벨 종류, 계층 시트, 전원 심볼을 앱이 KiCad와 똑같이 해석해야 한다. 어긋나면 엉뚱한 연결이 제안된다.
- **기호로 짝짓기:** KiCad에서 다시 주석을 달면 기호가 바뀌어 다른 부품에 변경이 붙는다.
- **바로 회로에 반영:** 외부 파일에서 온 변경도 다른 변경과 같이 비교 표를 보고 승인해야 한다(FR-16 단일 승인 경로).

## 확인

- `tests/test_kicad_edits.py`: 값·풋프린트·삭제, 핀 이동과 새 Net, 라벨 이름 변경, 자동 이름 Net, 가져오지 못하는 부품, API(오류 코드와 제안). KiCad 10.0.8로 실제 파일을 고쳐(R1 값, D1 삭제) kicad-cli로 읽어 확인했다.

## 남은 위험

- 추가한 부품의 위치는 자동 배치다(다음 가져오기에서 위치를 옮기면 그때 고정된다).
- 다중 유닛 부품의 유닛별 변경, 핀의 no-connect 표시 변경은 가져오지 않는다.
- 계층 시트를 KiCad에서 새로 만들면 페이지 구조(IR `sheets`)는 바뀌지 않는다. 연결만 가져온다.
