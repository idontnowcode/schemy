# 실제 흐름 시험 보고 — 24V CAN 온도 센서 노드 (2026-11-09)

사용자 요청: "네가 임의로 생성하는게 아니라, 실제 AI 모델로 돌려서 하나의 요구사항에 대한 진행 흐름대로 테스트를 해보고 디버깅 포인트를 찾아봐. 각 흐름 별로 캡쳐하면서." 이어서 "AI 모델 동작은 네가 대신 해."

## 방법

- 앱(백엔드 + 화면)을 그대로 띄우고, AI 공급자 자리에 중계 공급자(`tests/relay_backend.py`)를 넣었다. 앱이 보내는 프롬프트를 파일로 받아 Claude(이 세션)가 읽고 답을 써서 돌려준다. 미리 짠 각본은 없다.
- KiCad 10.0.8 공식 Docker 이미지로 ERC·Netlist를 실제로 돌렸고, 부품 해석은 그 이미지의 전체 심볼 라이브러리(224개)로 했다.
- 화면은 Playwright로 조작하며 단계마다 캡처했다. 캡처와 상세는 보고서 페이지(대화에 공유된 링크)에 있다.

요구사항: 24 V(18~32 V) 입력, STM32(CAN 내장)·SWD, CAN 트랜시버·점퍼 종단, 24 V → 3.3 V 강압·역전압·서지 보호, I2C 온도 센서, LED 2개, 4핀 단자대. AI 질문 답: 500 kbps, 24 V에서 50 mA 이하, 3.3 V 트랜시버, IEC 61000-4-5 ±1 kV · −40~85 °C, 절연 필요 없음.

## 결과

- 7단계 완주. AI 호출 8회(정리 1, 부품 계획 1, 연결 1, 검토 3, 수정안 편집 2). 제안 3개, #2 승인 → revision 1.
- 부품 39개 모두 KiCad 10 심볼로 해석, 연결 1회 통과, 지침 자동 점검 위반 없음, ERC 0/0, Netlist 일치.
- AI 검토 수정 권장 2개(벅 2.1 MHz 최소 온타임, 입력 감쇠 콘덴서) 모두 근거 확인됨 → 고칠 곳만 편집 15개로 수정안 #2 → 2회차 권장 1개에서 조건 충족으로 멈춤.

# 세 번째 실제 흐름 시험 — 「AI가 고칠 것 0」까지 (2026-11-09)

사용자 질문: "AI가 고칠 부분이 없게끔까지 만들 수는 없어?"

두 번째 시험과 같은 요구사항·보유 자재로 처음부터 다시 돌렸다(두 번째 시험에서 고친 것이 들어간 앱). 같은 방법: 중계 공급자로 Claude가 프롬프트마다 직접 답함, KiCad 10.0.8 Docker, Playwright 캡처.

## 결과

- **수정 필요 0 · 수정 권장 0으로 끝났다.** 남은 의견 두 개를 서로 다른 길로 닫았다.
  - 입력 TVS 클램프 전압 > LM2596 절대 최대(두 번째 시험 #35): AI가 "요구사항에 서지 레벨이 없고 템플릿·보유 자재를 바꿔야 해서 사람이 정해야 한다"며 고치지 않음 → 사람이 「의도한 설계로 두기」(제어반 내부, 보호된 SMPS 전원, 서지 시험 요구 없음) → 다시 실행하니 1회차에 AI 호출 없이 조건 충족.
  - 결정을 남긴 뒤 **새로 AI 검토**를 돌렸다: TVS는 다시 적지 않았고(회로가 그대로라 결정 이유가 유효), 앞 검토가 놓친 문제를 새로 찾았다 — 분압 저항이 1 %라 분압비 오차가 최악 약 1.5 %(RSS 1.06 %)로, 요구한 풀스케일 ±1 %를 교정 없이 보장하지 못함(근거: 요구사항 「풀스케일 ±1 %」, 앱이 확인함). 자동 반복 → AI가 R4~R7을 0.1 % 박막(RT0603BRD)으로 바꾼 편집 수정안 #2 → 2회차 0/0 → 승인 → revision 1, ERC 0/0, Netlist 일치.
- 즉 「0」은 **근거 있는 지적이 0**이라는 뜻이다. 사람이 정한 의견은 세지 않을 뿐 「사람이 정한 것 1개」로 이유와 함께 남고, 검토자에게 알려지며, 회로가 바뀌어 이유가 맞지 않으면 다시 적힐 수 있다. 결정 취소도 된다.
- AI 호출 11회: 정리 1, 부품 계획 1, 연결 1, 지침 점검 편집 1, 검토 3(첫 검토, 결정 뒤 새 검토, 수정안 검토), 수정안 편집 3(거절 2, 고침 1), 연구노트 1(검토 버튼이 함께 씀).
- 두 번째 시험에서 고친 것 확인: SM712가 3핀 심볼로, 2×3 ISP·5.08 mm 단자대·딥스위치 풋프린트 모두 맞음, 지침 점검은 실제 위반만, 4단계 줄이 결과를 유지, 5단계 처음 화면에 받은 검토가 보임(#38, 「남은 의견」 패널).

# 네 번째 실제 흐름 시험 — 설계 흐름 안의 데이터시트 (2026-11-12)

사용자 질문: "요구사항을 넣으면 앱이 회로도 작성과 검증까지, 추가 변경이 필요 없는 수준으로 가능한가?" 답은 「초안과 형식 검사까지는 되고, 변경 불필요는 보장하지 못한다」였고, 격차를 줄이는 첫 항목(데이터시트 받기·대조를 흐름에 넣기)을 사용자가 승인했다. 구현(ADR-005 추가 결정) 뒤 같은 요구사항·보유 자재로 4단계까지 돌렸다. 같은 방법: 중계 공급자로 Claude가 프롬프트마다 직접 답함, KiCad 10.0.8 Docker, Playwright 캡처. 데이터시트는 **실제 제조사 사이트에서 받았다**(이 환경에서 접속되는 곳은 TI뿐).

## 결과

- 3단계에서 「고른 부품의 데이터시트를 받아 대조」를 켠 채 「AI 설계 시작」. 부품 41개가 정해진 직후 데이터시트 단계가 돌았다.
  - LM4040B41IDBZR: ti.com에서 받음(86쪽) → 24쪽만 골라 AI 요약.
  - LM2596S-5.0(검토된 템플릿의 부품): ti.com에서 받음(47쪽) → 15쪽만 골라 AI 요약.
  - ATmega328P-AU(Microchip), MAX485ESA+(Maxim/ADI): 이 환경의 네트워크 정책으로 막혀 받지 못함. 설계는 계속됐고, 제안에 이유와 「브라우저에서 열기」가 남았다.
- **요약이 설계에 쓰였다.** 핀 연결 프롬프트에 LM4040 요약이 들어갔다(3번 핀은 띄우거나 애노드에, RS는 0.1~1 mA, 용량성 부하에 안정). AI는 3번 핀을 미연결로 두는 근거(40쪽)와 R8 1 kΩ의 전류 계산(42쪽)을 데이터시트 인용으로 남겼다.
- **요약이 검사와 검토에 쓰였다.** 제안 검사가 U3·U4를 데이터시트와 대조했고, AI 검토의 근거 목록에 대조 결과(E3·E4)와 요약(D1·D2)이 들어갔다. 검토자는 U4의 권장 공급 전압 4.5~40 V(D2)를 근거로 입력 TVS 의견을 냈고, 대조의 잘못된 「핀맵 불일치」는 이름 표기 차이라고 판단해 참고로만 적었다.
- AI 호출 6회: 부품 계획 1, 데이터시트 요약 2, 핀 연결 1, 지침 점검 편집 1, 검토 1. 설계 job 4분 35초(요약을 사람이 쓴 시간 포함), ERC 0/0, Netlist 일치, 검토 결과 수정 필요 0 · 권장 2(분압 저항 정확도, 입력 TVS — 세 번째 시험과 같은 두 의견).
- 자동 반복과 승인은 세 번째 시험에서 확인한 것과 같아 다시 돌리지 않았다.

## 한계

- **이 환경에서는 TI만 받았다.** Microchip·Maxim은 네트워크 정책으로 막혔다(403). 사용자 PC에서는 사이트마다 결과가 다를 것이다(ADR-005의 남은 위험과 같음).
- **요약은 Claude가 썼다.** 앱이 고른 쪽의 글자를 뽑아 읽고, LM2596은 1쪽의 응용 회로 그림을 직접 보고 썼다. 실제 모델이 PDF를 읽고 같은 품질로 쓰는지는 재지 않았다.
- **AI 요약은 사람이 원문과 확인하기 전이다.** 화면에 그렇게 표시된다. 대조 결과는 "요약이 맞다면"의 근거다.
- **MCU처럼 수백 쪽인 데이터시트**는 쪽 고르기로 보낼 수 있게 됐지만, 이번에는 받지 못해 실제로 요약해 보지 않았다.
