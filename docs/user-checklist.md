# 사용자가 할 일 (체크리스트)

이 개발 환경에서는 할 수 없는 일만 남겼습니다. 각 항목에 무엇을 하고, 무엇을 알려 주면 되는지 적었습니다. 결과를 알려 주시면 그다음은 제가 고칩니다.

---

## 1. Windows 설치 파일 설치·실행 확인 (10분)

GitHub Actions(windows-latest)에서 설치 파일을 만들었습니다. 같은 실행에서 동봉한 백엔드가 Windows에서 뜨고 LED 예제 회로도를 만드는 것까지 자동으로 확인합니다. 실제 PC에서의 설치와 화면은 아직 확인하지 않았습니다.

### 준비
- [ ] KiCad 10 설치 (https://www.kicad.org/download/windows/). 설치 파일에는 KiCad가 들어 있지 않습니다.

### 받기
- [ ] GitHub 저장소 → **Actions** → **Windows installer** → 맨 위(가장 최근) 실행 → 아래쪽 **Artifacts**의 `AI-Circuit-Studio-Setup`을 받습니다.
  - 가장 최근 실행(ChatGPT 로그인·데이터시트 찾기 포함): https://github.com/idontnowcode/schemy/actions/runs/42058431083
  - zip을 풀면 `AI-Circuit-Studio-Setup-0.1.0.exe`가 있습니다. Artifacts는 90일 뒤 지워집니다.

### 설치와 확인
- [ ] exe 실행. 코드 서명이 없어서 SmartScreen이 막으면 **추가 정보 → 실행**을 누릅니다.
- [ ] 앱이 열리고 왼쪽 아래에 `KiCad: 10.0.x`가 보이는지 확인합니다. 보이지 않으면 KiCad를 찾지 못한 것입니다.
- [ ] 새 프로젝트를 만들고 **고급 화면(탭)** → **설계 → 회로 데이터** 탭 → **예제 불러오기**에서 `lm7805-24v-to-5v`를 고른 뒤 **저장**합니다.
- [ ] **회로도 · 검증** 탭 → **회로도 생성**을 누르고 `Automated checks passed`가 나오는지 확인합니다.
- [ ] **KiCad에서 열기**를 눌러 KiCad에서 회로도가 열리는지 확인합니다.
- [ ] **검토** 탭에서 기술 검토 결과(주의 1: 발열 1.81 W)와 「전원 조건」 표가 보이는지 확인합니다.
- [ ] (선택) KiCad에서 R1 값을 바꾸고 저장한 뒤 **고친 것 모두 가져오기**를 누르면 제안이 만들어지는지 확인합니다.

### 문제가 생기면 알려 줄 것
- 오류 창의 글(앱이 "백엔드가 종료되었습니다…"를 띄우면 그 내용 전부)
- 화면 캡처
- 어느 단계에서 멈췄는지

## 2. 실제 AI로 시험 (30분~1시간, API 크레딧 또는 ChatGPT 요금제 사용)

AI 설계·검토·Agent는 지금까지 각본대로 답하는 가짜 AI로만 시험했습니다. 실제 모델이 회로를 얼마나 잘 만드는지는 아직 모릅니다.

### 준비
- [ ] 앱 **설정** → 공급자 선택 → 연결 → **AI 기능 사용** 켜기
  - Gemini: API 키 저장. Claude: **Claude 로그인**(Console 계정) 또는 API 키.
  - ChatGPT: **ChatGPT로 계속하기** → 브라우저에서 로그인 → 이 앱 등록과 「ChatGPT 요금제 사용」 허용. 설정 화면에 이메일과 "요금제 사용 허용됨"이 보이면 됩니다. **이 로그인은 실제 계정으로 아직 해 보지 않았습니다.** 안 되면 브라우저 화면의 오류 글과 설정 화면의 빨간 글을 알려 주세요.
  - 키는 Windows 자격 증명 관리자에만 저장되고, 프로젝트 파일과 기록에는 남지 않습니다.
  - AI를 부를 때마다 무엇을 보내는지 먼저 보여 주고 확인을 받습니다. 회사 회로도라면 사내 규정을 먼저 확인하세요.
- [ ] 설정 › 모델의 **연결 시험**을 눌러 「연결됨: 모델 · ms · 응답 "OK"」가 나오는지 확인(고정 문장 한 줄만 보냄). 오류가 나오면 그 글을 알려 주세요.

### 시험 0: AI 성능 평가로 한 번에 재기 (권장, AI 호출 약 52회)
- [ ] 사이드바 **AI 성능 평가** → 묶음 셋(설계·검토·연구노트) 모두, 반복 1회 → **평가 실행**(확인 창에 받는 곳·보낼 것·호출 수가 나옴)
- [ ] 끝나면 기록 표의 설계 완료·요구 충족·결함 탐지·노트 근거 인용을 보고, 행을 열어 **보고서 받기**로 받은 Markdown을 저에게 주세요. 이 숫자가 이 앱의 첫 실측입니다.
- [ ] 여유가 있으면 모델을 바꿔(예: Gemini Flash ↔ Pro, Claude Opus ↔ Sonnet) 한 번 더 돌려 비교하고, 반복 3회로 결과가 얼마나 흔들리는지도 봐 주세요.
- 회사 PC에 KiCad 10이 설치되어 있으면 설계 묶음에서 KiCad 검사까지 합니다(없으면 「검사 안 함」으로 표시되고 통과로 세지 않음).

### 시험 1: AI 회로 설계 (예제 요구사항 그대로)
- [ ] 새 프로젝트 → **요구사항** 탭에 `examples/lm7805-24v-to-5v/requirements.md` 내용을 붙여 넣고 저장 → **AI로 회로 설계**
- [ ] 같은 방법으로 `examples/ne555-led-board/requirements.md`도 시험
- [ ] 각각 확인할 것:
  - 제안이 만들어졌는지, KiCad 검사(ERC·Netlist)를 통과했는지
  - 제안 비교 표의 「설계 결정과 근거」가 부품마다 채워졌는지, 「요구 수정」이 있다면 원래 요청이 적혔는지
  - 「전원 조건」에 전압·부하 전류가 들어왔는지
  - 「검토」 탭 기술 검토에 실패(빨강)가 있는지

### 시험 2: AI 검토와 수정안
- [ ] 저장된 회로에서 **AI 검토** → 의견 하나를 골라 **수정안 만들기** → 비교 표 확인

### 시험 3: Agent
- [ ] **Agent** 탭에 "R1을 1k로 바꿔줘"처럼 작은 변경을 요청 → 계획·범위 승인 → 결과 제안 확인

### 알려 줄 것
- 시험마다 성공/실패, 걸린 시간, 이상했던 점(엉뚱한 부품, 빠진 연결, 비어 있는 근거)
- AI 호출 기록 파일: 프로젝트 폴더의 `boards/a/ai_runs/*.json`(사용 토큰이 들어 있고 API 키는 없음). 그대로 보내 주시면 프롬프트와 상한을 조정합니다.
  - 프로젝트 폴더: `문서\AI Circuit Studio\projects\<프로젝트 id>\`

## 2-1. 데이터시트 찾기 시험 (15분, 선택: Mouser·DigiKey 키)

이 개발 환경에서는 TI 사이트에서만 실제로 받아 보았습니다. 회사 PC의 인터넷·방화벽에서 되는지 확인해 주세요.

- [ ] 모터 예제(`dc-motor-drv8871`)를 저장 → **데이터시트** 탭 → 「데이터시트 찾기」에서 U1의 받을 곳을 「제조사 사이트: www.ti.com」으로 고르고 **선택한 곳에서 받기**
  - 기대: 「제조사 사이트에서 받음 · 제품군 확인됨」
- [ ] (선택) ST 부품이 있는 회로에서 ST 사이트로 받기 → 실패하면 **브라우저에서 열기**가 제품 페이지·PDF를 여는지
- [ ] (선택) 설정 › 데이터시트 검색에 키 저장 → **유통사에서 찾기** → 받을 곳에 「DigiKey」·「Mouser」가 생기는지 → 받기
  - Mouser: https://www.mouser.com/api-hub/ 에서 Search API 키
  - DigiKey: https://developer.digikey.com/ 에서 앱을 만들고 Product Information v4를 구독 → Client ID·Secret
- [ ] 회사 프록시 때문에 실패하면 시스템 프록시(HTTPS_PROXY)를 설정한 뒤 다시 시험
- [ ] (키가 있으면) MPN이 있는 보드(I2C 예제 등)에서 **문서 · BOM → 유통사 재고·가격 조회** → 재고·단가·상태가 나오는지. 이 기능도 실제 키로는 아직 호출해 보지 않았습니다.

### 알려 줄 것
- 어느 사이트에서 성공/실패했는지, 실패 메시지(오류 코드 포함)

앱 기본 지침 30개는 일반 설계 관행으로 썼습니다. 회사 기준과 맞는지 한 번 봐 주세요.

## 2-3. 연구노트 시험 (15분, 실제 AI 필요)

연구노트는 가짜 AI로만 시험했습니다. 실제 모델이 동료가 읽을 만한 노트를 쓰는지 봐 주세요.

- [ ] I2C 예제(`i2c-sensor-3v3`)나 실제 보드를 저장 → **검토** 탭 → 연구노트 카드에서 **AI로 연구노트 쓰기**(특히 다룰 것은 비워도 됨)
- [ ] 노트를 열어 확인: 배운 점이 이 보드만의 사실이 아니라 다른 회로에도 통하는 교훈인지, 근거 번호(E1 …)가 맞는 근거를 가리키는지, 「근거 없음」 표시가 붙은 문장이 실제로 확인이 필요한 문장인지
- [ ] 틀린 곳은 **고치기**로 고치고 **검토함으로 표시**, 쓸 만한 「다음 설계에 적용할 것」은 **지침 후보로**
- [ ] **제안** 탭에서 「AI 검토 때 연구노트도 쓰기」를 켠 채로 AI 검토를 한 번 더 해 보기
- [ ] 사이드바 **연구노트** → **모두 Markdown으로 받기**로 받은 파일을 팀원이 읽고 이해하는지

### 알려 줄 것
- 노트가 너무 길거나 짧은지, 빠진 절이나 필요 없는 절, 근거 번호가 틀린 예

## 2-4. 검사 경고와 고치기 버튼 확인 (5분)

- [ ] 「ERC 오류 0, 경고 N」이 나오던 보드에서 「회로도 · 검증」 → **다시 생성**. 이제 생성 프로젝트에 KiCad 라이브러리 표가 함께 들어가, 부품마다 나던 「라이브러리 설정 없음」 경고(lib_symbol_issues, footprint_link_issues)가 사라져야 합니다. 경고 수 옆에 「회로 a · 이 컴퓨터 KiCad 설정 b」가 나오면 b가 0인지 봐 주세요.
- [ ] 남은 경고가 있으면 그 종류(경고 옆 회색 코드)를 알려 주세요. 회로 문제면 아래에 「바로 고치기」 또는 「AI로 검사 문제 고치기」가 나옵니다.
- [ ] 승인한 제안의 AI 검토 의견에 「이 의견 반영하기」가 보이는지(지금 회로가 그 제안의 revision일 때). 회색으로 비활성이면 마우스를 올려 이유를 확인하세요.

### 알려 줄 것
- 다시 생성한 뒤의 경고 수와 종류, 버튼이 안 보이거나 이유가 이해되지 않는 화면

## 3. 데이터시트 원문 대조 (엔지니어 검토)

앱이 적은 근거 중 데이터시트 쪽 번호와 일부 값은 원문을 보지 못해 "원문 확인 필요" 또는 "일반값"으로 남아 있습니다. 엔지니어가 원문을 보고 확정해야 합니다.

### 확인할 값

| 대상 | 확인할 것 | 지금 적힌 값 |
|---|---|---|
| L7805 (7805 예제) | 최대 입력 전압, TO-220 접합-주변 열저항, 최대 접합 온도, 드롭아웃, 응용 회로의 입출력 콘덴서 | 35 V, 약 50 °C/W, 125 °C, 약 2 V, 0.33 µF / 0.1 µF |
| 1N4007 / 1N4001 | 평균 순방향 전류, 최대 역전압(VRRM), 순방향 전압 | 1 A, 1000 V / 50 V, 약 1 V |
| AMS1117 템플릿 | 입출력 콘덴서, 드롭아웃, 최대 전류 | 템플릿의 데이터시트 절 |
| LM2596S-5 템플릿 | 인덕터·다이오드·콘덴서 값 | 템플릿의 데이터시트 절 |
| SN65HVD230 템플릿 | 종단 저항, Rs 핀, 디커플링 | 템플릿의 데이터시트 절 |
| ATmega328P 템플릿 | 디커플링, 크리스탈 부하 콘덴서, RESET 풀업 | 템플릿의 데이터시트 절 |
| SRD-12VDC-SL-C (릴레이 예제) | 핀 배치: 3·4번 중 NO·NC, 코일 전류, 접점 정격 | KiCad 심볼은 3·4를 접점으로만 앎(회로도 주석 「Check NO/NC pins」) |
| PC817C (절연 입력 예제) | If = 1 mA 근처 CTR(곡선), CTR 최대, 응답 시간 | 계산은 If 5 mA 기준 200~400 % |
| AO3400A (릴레이 예제) | Vgs(th) 최대, Rds(on)이 규정된 가장 낮은 Vgs, Vds | 1.45 V, 2.5 V, 30 V(대표값 표) |
| MCP6001, BAT54S (0~10 V 입력 예제) | OP앰프 입력 최대 정격(VDD + ?), BAT54S VRRM | 데이터시트 요약 없음 |
| SMAJ5.0A + AP2112K, SM712 + MAX3485 | TVS 클램프 전압 vs 보호하는 IC 핀의 최대 정격 | 데이터시트 요약 없음 |
| CT SCU 메인보드 (scu-main-board) | TPS54360 보상·UVLO, TPS3430 SET/CWD 표, MCP130 임계값, LAN8742A 마그네틱 연결, STM32 핀 대체 기능(CubeMX), BSP75N 3.3 V 구동 | `examples/scu-main-board/README.md` 「확인할 것」 |

실무 회로 다섯 개는 폴더의 `research-note.md` 「열린 질문」에 확인할 것이 정리되어 있습니다. 예제마다 `rationale.md`의 「출처」 줄에 "원문 확인 필요"가 붙은 항목도 같은 방법으로 확인합니다.

### 하는 방법
- [ ] 보드의 **데이터시트** 탭에서 데이터시트를 받거나(제조사 링크) PDF를 직접 올립니다.
- [ ] **검토** 탭에 검토 기록을 남깁니다: 검토자, 데이터시트 문서 번호·개정, 확인한 쪽, 항목별 결과.
  - 이 기록만 「엔지니어링 검토」 상태를 `verified`로 바꿉니다.

### 알려 줄 것
- 값이 다른 항목과 원문의 쪽 번호. 템플릿 값과 근거를 v2로 고치고, 기술 검토의 일반값도 바로잡습니다.
